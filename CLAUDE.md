## Objectif Final
Construire Plotline, un SaaS de gestion de personas IA pour createurs d'influenceurs IA sur Instagram et TikTok.

Le produit permet de configurer un ou plusieurs personas (identite visuelle, voix, piliers de contenu, style narratif, frequence de publication) puis de generer automatiquement des batchs de contenus coherents (image + caption + hashtags), avec validation humaine avant publication.

---

## Stack Technique
- Nuxt 3 monorepo (Vue 3 front + server routes back)
- Prisma + PostgreSQL
- BullMQ + Redis
- SDK Anthropic JS (claude-sonnet-4-6)
- Deploy VPS Hostinger
- Domaine cible: plotline.sassify.fr
- Email: SMTP Hostinger via variables d'environnement

## Conventions IA et Code
- Toute la logique serveur vit dans server/utils et server/api.
- Les utilitaires dans server/utils sont des fonctions pures exportees.
- Le format de sortie de Claude est toujours du JSON brut, sans markdown.
- UI : le kit visuel vit dans `docs/ui-kit/` (`UI.md` = regles, tokens et composants ; `ui-kit-v1.png` = reference visuelle). Il s applique au fil de l eau : quand on cree OU retouche une page pour une raison fonctionnelle, on la fait conforme au kit (composants `Ui*`, tokens, regles de `UI.md`). On ne migre PAS les pages qu on ne touche pas : l etape 3 de la "Mission" de `UI.md` ("toutes les pages") est volontairement ecartee, decision de l utilisateur du 2026-10-09 pour ne pas se disperser. Etat (2026-10-09) : les 17 composants du kit existent dans `app/components/ui/` (`UiButton`, `UiField`, `UiInput`, `UiTextarea`, `UiSelect`, `UiSlider`, `UiTagInput`, `UiSegmented`, `UiToggleChips`, `UiBadge`, `UiProgress`, `UiSkeleton`, `UiCard`, `UiAlert`, `UiEmptyState`, `UiSectionNav`, `UiIconButton` ; `UiConfirmDialog` et `UiToastStack` sont anterieurs au kit). ECARTS volontaires avec `UI.md` : (1) les tokens Tailwind sont sous le prefixe `ui-` (`bg-ui-accent`, `text-ui-ink-2`, `border-ui-line`, `rounded-ui-card`...) car `accent`, `border`, `muted` et `rounded-card` existent deja avec d autres valeurs (utilises par les pages actuelles) ; (2) Geist n est PAS la police globale : elle s applique via `font-ui` / `font-ui-mono`, donc seulement dans les composants `Ui*` et les pages migrees ; elle passera en police par defaut quand la plupart des pages auront migre. Premiere page migree : `/admin/personality`. CONTROLE AUTOMATIQUE (2026-10-16, la regle seule ne tenait pas : elle repose sur la vigilance de l IA et a ete oubliee sur `/library/fiches`) : deux hooks (`.claude/settings.json` -> `scripts/check-ui-kit.mjs`) : PostToolUse (juste apres chaque Write/Edit d un .vue : retour immediat) et Stop (fin de tour), qui examinent les fichiers `.vue` de `app/` modifies ou nouveaux (hors `app/components/ui/`) et REFUSE de terminer le tour (exit 2, message renvoye a l IA) s ils contiennent une couleur en dur (`bg-[#...]`, `style="...#..."`, `rgba(...)` entre crochets) ou une couleur Tailwind par defaut (`text-gray-500`, `bg-red-50`...). Perimetre (decision de l utilisateur du 2026-10-22, la regle des lignes seules laissait les pages anciennes en couleurs en dur) : STRICT PAR DEFAUT, un .vue touche doit etre ENTIEREMENT conforme, toutes ses lignes ; `UI_KIT_STRICT=0` ne controle que les lignes ajoutees (`git diff HEAD`). Le script se replace tout seul a la racine du depot (`CLAUDE_PROJECT_DIR`, sinon cwd) : avant, depuis un sous-dossier, il repondait « tout va bien » a tort. Le shell global (`app/components/layout/PlotlineShell.vue`, barre laterale) est migre aussi (2026-10-22) : RAIL COMPACT d icones lucide par defaut sur bureau (comme la maquette du kit), bouton pour deplier les libelles, choix memorise par le cookie `plotline-sidebar` (`rail` | `full`), tiroir mobile avec libelles, modale d onboarding refaite en carte du kit ; le fond general de l application passe donc a `ui-bg` (#F7F6F3) au lieu de #FAFAF8. Premiere page migree en entier par ce mecanisme : `/studio` (137 couleurs en dur -> 0, composants UiButton / UiSegmented / UiTextarea ; selects natifs et radios restent natifs mais avec tokens). Restent avec couleurs en dur (fichiers non touches) : `ReviewDialog`, `LibraryAssetPicker`, `EditSlideStrip` et les autres pages jamais retouchees : le controle les saisira la premiere fois qu on y touche. Echappatoire visible : le mot `ui-kit-ignore` sur la ligne, seulement quand le kit n a pas d equivalent (ex. champ fichier natif) et en le disant a l utilisateur. Ne controle que les couleurs : le choix des composants `Ui*` (UiButton, UiField...) reste a la charge de l IA. Il ne controle que le travail NON COMMITE (`git diff HEAD`) : un fichier deja commite n est plus examine.

## Blocages et Points d Attention
- Le dossier cible initial n'etait pas vide; un sous-dossier plotline etait deja initialise. Le projet actif est a la racine actuelle.
- La coherence visuelle repose sur un identity lock par reference fixe, sans seed/fine-tune.
- Aucune publication automatique sans validation humaine explicite. C est une regle d etape, pas un principe definitif: l automatisation pourra etre ouverte plus tard, mais uniquement sur decision explicite du proprietaire du produit, apres un volume de publications manuelles jugees majoritairement de qualite. Aucun seuil automatique, aucune proposition du produit, et aucun agent ne leve cette regle de sa propre initiative. Elle est appliquee dans le code par `scheduledPublisher`, qui ne publie que les contenus VALIDATED.
- Toujours separer clairement generation et publication.
- Les migrations ne sont JAMAIS executees depuis le projet: on ecrit le SQL dans `prisma/migrations/`, et il est passe a la main via l'editeur SQL de Neon. Le port 5432 est bloque sur le reseau, la connexion passe par WebSocket (`@prisma/adapter-neon`, port 443).
- Ne jamais ajouter un champ scalaire au schema Prisma avant que la migration soit appliquee: le client selectionne toutes les colonnes du modele et toutes les lectures cassent. Voir tasks/lessons.md.
- Le workflow Pinterest est interdit aux comptes BRAND et CONTENT_CREATOR.
- Un compte INFLUENCER_CREATOR se lit comme une agence d influenceurs virtuels: beaucoup d influenceurs, peu de marques.
- Le rattachement marque <-> ambassadrice est volontairement limite a un seul compte. On ne relie jamais deux profils de comptes differents.
- Aucune generation media ne doit etre attendue dans une requete HTTP: reponse immediate en `processing`, suivi par polling.
- Les binaires ffmpeg/ffprobe sont resolus a l EXECUTION (`server/utils/ffmpegBinaries.js`), jamais importes statiquement: npm bloque les scripts d installation, et un import statique faisait echouer tout le build sur le serveur. Ordre de resolution: `FFMPEG_PATH`/`FFPROBE_PATH`, puis le paquet npm, puis le binaire systeme. ffmpeg ne sert qu au workflow Reel Pinterest.
- Le cookie de `state` OAuth Google (`GOOGLE_STATE_COOKIE`) n'est pas isole par port: deux projets Nuxt en local sur des ports differents partagent leurs cookies et se font ecraser leur `state` mutuellement. Voir `docs/recette-connexion-google.md` avant de reactiver du dev local en parallele d'un autre projet ayant aussi du Google OAuth.
- L URI de redirection Google (`server/utils/googleOAuth.js`, `pickOAuthBaseUrl`) doit toujours faire primer `BASE_URL` sur l origine de la requete: derriere le reverse proxy du VPS, lire l origine sans `xForwardedHost`/`xForwardedProto` renvoie l adresse interne du serveur, que Google refuse (`redirect_uri_mismatch`). Ne pas re-inverser cette priorite sans relire tasks/lessons.md (2026-09-03, deja fait une fois par erreur).
- `getBodyBlock(silhouette, gender, topGarment)` (`server/utils/injectBody.js`) prend le genre en 2e argument depuis le 2026-09-06. Toute nouvelle fonction qui l appelle doit passer le genre du profil, sinon la description corporelle retombe au feminin par defaut.
- `POST /api/external/video-jobs` (branche `feature/external-video-jobs`) est un point d entree service-a-service sans session, protege par `EXTERNAL_VIDEO_JOBS_API_KEY` (cle partagee inventee, a generer et poser identiquement sur le VPS Plotline et sur l appelant). Si la variable est absente, l endpoint refuse tout en 503 plutot que de s ouvrir sans protection -- ne jamais retirer cette garde. Ce endpoint ne fait volontairement aucun overlay texte: les videos qu il produit doivent rester des videos "normales" (type pub), sans texte par dessus.
- Le suivi de statut existant (`GET /api/content/:id/status`) exige une session utilisateur (`requireAuthUser`) et scope la requete par `userId`: inutilisable par un appelant service-a-service. D ou `GET /api/external/video-jobs/:id/status`, un jumeau sans scoping utilisateur, protege par la meme cle partagee. Trouve et corrige en testant `POST /api/external/video-jobs` en conditions reelles -- sans lui, home.sassify.fr n aurait eu aucun moyen de savoir quand sa video est prete.
- Pour ce meme endpoint externe, l identite du persona n est plus verrouillee par defaut (decision du 2026-09-09) : sur Omni Flash, verrouiller l identite via une image de depart casse le lip-sync (voix off), et le flux a deux tours qui le repare derive sur l identite et casse en debut/fin de clip -- non corrige par ajustement de prompt. Pour du contenu qui n a pas besoin de continuite de personnage (illustrer un article de blog), le modele invente desormais librement qui apparait a l ecran : plus fiable, moins cher. Le flux a deux tours reste dans le code (`requestOmniFlashTwoTurn`), disponible des qu une image de depart est fournie -- utile pour du contenu Plotline classique ou l identite doit rester verrouillee malgre ces defauts connus.
- Le dossier de travail de ce projet est potentiellement partage avec l utilisateur (qui commite et change de branche depuis son propre terminal) ou une autre session Claude Code, pas seulement avec la session en cours. Un `git checkout`/`git stash` externe peut survenir pendant une implementation et faire disparaitre des fichiers non commites du disque sans prevenir -- voir tasks/lessons.md (2026-09-10) avant de conclure a une perte de donnees : verifier `git stash list`/`git reflog` en premier, jamais re-ecrire a l aveugle.
- Le tick du scheduler de publication (`server/plugins/scheduler.ts`) et les intervalles du worker BullMQ (`server/utils/generationWorker.js`, `drainDelay`/`stalledInterval`) tournent 24h/24 des que le process est en vie, independamment du trafic reel. A la frequence par defaut (60s / 30s), ce bruit de fond a lui seul epuise le quota mensuel gratuit de Neon (CU-hours, la base ne peut jamais se mettre en veille) et d Upstash Redis (commandes). Passes a 10 minutes et 5 minutes respectivement (2026-09-13/14) -- un job reel reste pris en charge immediatement, seules les relances a vide sont espacees. Ne jamais reprendre un intervalle par defaut d une lib (BullMQ, cron) sans se demander a quelle frequence ca interroge un service externe facture/quota a l usage.
- Sur la machine de dev Windows utilisee pour ce projet, `http://localhost:<port>` peut repondre `426 Upgrade Required` sur un serveur Nuxt qui fonctionne pourtant tres bien -- `http://127.0.0.1:<port>` fonctionne normalement. Cause non elucidee (probablement une resolution `localhost` -> IPv6 qui ne tape pas le meme bind que le serveur). Utiliser `127.0.0.1` pour toute verification navigateur en local sur cette machine si `localhost` renvoie une erreur inattendue.
- Plusieurs routes de `server/api/profiles/` exportent encore via `module.exports = defineEventHandler(...)` (style CJS) plutot que `export default`. Rollup (`npm run build`) tolere le melange avec un `import` ESM statique ajoute en tete de fichier, mais le serveur de dev (Nitro/Vite) non: la presence d un `import` force Node a charger tout le fichier en ESM strict, ou `module` n existe pas, et l exception casse l enregistrement de TOUTES les routes, pas seulement celle du fichier fautif (`Cannot access 'renderer' before initialization`). Avant d ajouter un `import` statique a un fichier existant de ce dossier, verifier son style d export (`grep module.exports`) et le convertir en `export default` au meme moment si besoin -- voir tasks/lessons.md (2026-09-16).
